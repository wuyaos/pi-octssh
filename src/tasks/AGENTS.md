# src/tasks：任务状态、恢复、投递与持久化

远端 screen 任务与进程内异步传输的生命周期不同，本模块负责把两者表达成同一套状态。

## 入口

- `state.ts`：状态机、可达性分离、取消语义、稳定 `eventId`
- `recovery.ts`：由「旧记录 + 本次观测」算新状态与应发事件
- `delivery.ts`：投递去重、单观察者租约、忙碌/无会话排队
- `store.ts`：`<OCTSSH_HOME>/tasks/` 下落盘索引、队列、已投递集、租约
- `notify.ts`：`runTaskSweep` 一轮扫描的注入式编排

## 契约

- 任务状态与**可达性**分开：`observation: "unknown"` 只更新可达性，不改任务状态、不产生事件。
- `eventId` 只由 `(taskId, 终态)` 决定——不得掺入时间、随机数或扫描序号，否则去重失效。
- 终态事件只发一次；已发过的判据是记录里的 `emittedEventId`，不靠时间或计数。
- 无同项目会话 → **不产生事件**，靠下一轮重新推导（不写 `emittedEventId`）；忙碌 → 入队等 `flush`。两条路径语义不同，不要合并。
- 缺 `projectId` 的旧记录不猜归属：记入 `notAwakened`，不投递。
- 租约：**异机持有者永不可抢**（判断在库内，不依赖注入实现）；同机且 pid 不存在（`ESRCH`）才可接管。
- 通知 payload 默认只含状态元数据，不含 stdout/stderr 或完整命令。

## 坑

- **`withLock` 不可重入**：`store.ts` 的写路径已持锁，锁内不得再调用任何需要取锁的 store 方法（嵌套会自死锁）。迁移读写要在同一次持锁里完成。
- `loadTasks()` 在索引损坏或版本过高时**不抛错**，而是返回空并置 `storeCorrupt` —— 调用方必须检查该标记，否则会表现成「没有任何任务」。损坏文件改名保留，不从空静默继续。
- 已投递记录的 v1→v2 迁移把无时间戳的旧条目视为**永不被时间裁剪**：宁可记得久，也不要因缺时间而重复唤醒。
- 裁剪只碰已投递集，队列独立。
- 进程内异步传输不承诺跨重启续存，重启后归 `interrupted`；不要试图「恢复」它。
