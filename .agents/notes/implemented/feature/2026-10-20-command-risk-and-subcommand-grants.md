# Agent Note: 查询放行与受限子命令授权

Status: implemented

## Problem

无规则也询问导致查询反复打断；防火墙工具整体禁止连查询也拦。已授权分支早于根目录删除检查，且自定义危险模式被强制要求 rm 预览，不能处理服务或容器操作。

## Decision

命令入口把 no_rule/no_project 与显式项目 ask 区分：简单普通命令默认放行，显式 ask/deny 保留。远端 read 无匹配规则时也不询问。权限裁决函数本身仍返回 no_rule 的 ask，避免改变其他调用方语义。sudo、识别到的删除/权限/服务/容器/软件修改以及复杂 shell 请求确认；不是完整的危险行为检测，脚本内部行为仍依赖操作者对模型的信任。

防火墙只放行明确列举的简单查询形式，非查询保留原禁止；用户显式 denyExecutables 不被查询例外覆盖。根目录删除检查在任何授权放行之前。非 rm 风险采用完整命令预览，不要求删除目标。

永久规则新增 command.match=subcommand，默认缺省仍精确匹配。首版只支持 docker 与 systemctl 的已知动作，多级 Docker 命令必须指定具体动作。参数可变，但复杂 shell、变量替换、通配 shell、目标切换参数不匹配。sudo 与项目和 SSH 身份仍独立匹配；禁止不被 allow 覆盖。UI 先选择永久允许，再显式选择完整命令或子命令范围，并在规则列表展示星号。

## Alternatives considered

- 任意字符串前缀或 docker *：方便但混合查询和删除，也可能放行 shell 串联，不采用。
- 把所有 no_rule 改 allow：会直接影响编辑和覆盖语义，因此只在命令/read 入口应用默认行为。
- 通用 shell AST 与风险分析：覆盖更广但复杂度高且仍无法解释任意脚本。本版保守拒绝复杂命令的子命令授权，保留精确确认。

## Consequences

子命令授权包含其参数表达的副作用，例如 docker exec 的执行能力，不能作为只读沙箱。防火墙查询白名单并不覆盖所有合法查询写法，未支持写法仍可能被拦。复杂只读管道也会询问。

新字段是严格规则格式的扩展：旧版读取器遇到含 match 的新规则会拒绝，不会静默放行；回退前应撤销新规则。现有无 match 规则保持兼容。

本轮类型检查、风险/规则/传输/取消相关 28 项测试通过，新增反例包括 shell 串联、变量替换、前置 context、动作变化、sudo 变化、授权后根删除。真实 Pi 永久范围弹窗和真实主机尚未验收。

历史审计：[v1 契约](../../proposed/architecture/2026-10-17-octssh-v1-contract.md)的精确命令规则继续保留，本次用户明确批准的子命令规则是新增类型，不把旧精确规则改为前缀。项目 AGENTS.md 未改写，后续维护应结合本次显式授权决定。
