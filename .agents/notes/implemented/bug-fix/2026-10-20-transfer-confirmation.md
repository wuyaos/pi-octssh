# Agent Note: 传输授权上下文与单次确认

Status: implemented

## Problem

扩展计算了项目身份，却没有传给传输 Runtime；下载重入还漏传授权 token。结果是项目规则失效、下载连续询问。上传先消耗项目确认 token，再请求覆盖确认，重入又回到项目确认，形成两关循环。

## Decision

四种传输形态都传递宿主项目身份和一次性授权。上传先对请求路径裁决 deny，再进行只读规划，把项目 ask 与覆盖清单合成一次确认。重入重新规划并比较包含项目、同步形态和冲突清单的授权摘要，冲突变化仍需重新确认。

规划后对实际目标文件再裁决规则，永久范围只允许单文件且绑定实际目标；目录上传不提供永久选项。已有项目 allow 可以免去其实际目标上的覆盖确认，显式 ask 仍优先。读取实际目标清单需要连接，不能声称目录内每个子路径的 deny 都在连接前完成；原始请求路径的 deny 仍在连接前返回。

## Alternatives considered

- 保留两次确认并复用 token：现有 token 是一次性能力，复用会扩大有效期与消费范围；合并为同一预览更简单且用户可理解。
- 把输入目录永久授权：最省交互，但实际覆盖范围可能比本次展示大，因此只为单文件生成永久规则。

## Consequences

项目 ask 的上传现在需要先连接并读取覆盖清单，但确认前不写入上传内容。此修复不改变整体 no_rule 默认策略，不实现子命令通配；这些是下一阶段独立变更。

5 项新增测试验证一次确认完成上传、deny 建连前阻止、单文件永久范围与回放、目录不提供永久范围，以及实际注册工具的四种传输形态均传递项目身份和 token。类型检查和原有权限测试通过；未做真实远端传输验收。
